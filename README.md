# XCoze-PairCraft

**和 AI 一起梳理需求、做评审原型、按反馈精准改版。**

XCoze-PairCraft 是一个面向产品经理和设计协作者的 Agent Skill。你可以带着一句产品想法、一份已有需求，或一轮客户反馈开始。它帮助 AI 判断这轮该讨论什么、该做什么，以及用什么成果来确认方向。

它来自一个实际问题：AI 很快就能生成 HTML Demo，但产品经理很难接手修改；一句「把这里改一下」也容易被理解成重做整页。PairCraft 把需求决定、设计稿和可运行原型关联起来，让你能找到具体修改对象、控制改动范围，并检查它是否符合预期。

## 什么时候用

| 你手上有什么 | 可以让 PairCraft 做什么 |
| --- | --- |
| 一个还不清楚的想法 | 梳理目标用户、使用场景和首版范围，挑出需要你拍板的问题 |
| 一个要给客户评审的方案 | 选出要验证的核心路径，制作流程图、线框或可点击原型，配上评审任务 |
| 一个已有原型和几条反馈 | 把反馈定位到页面、组件或业务规则，明确这次改什么、保留什么，再按预期检查结果 |

## 怎么一起工作

1. **对齐这轮任务。** 先读已有材料，区分已经确认的决定、AI 的建议和待澄清问题。你可以明确说「这轮只讨论」或「按现有方案直接改」。
2. **把想法做成你能检查的东西。** 用足够小的成果推进：需求摘要、主流程、可编辑线框，或一条可以实际点通的原型路径。你决定影响范围、用户体验或业务规则的取舍。
3. **让下一次修改有明确入口。** 根据反馈定位修改对象，记录对流程和页面的影响，更新应该维护的源稿，并复查相关路径。项目长到需要交接时，再记录版本和未决问题。

产品设计是主场景。共同理解目标、由人决定关键取舍、用可编辑成果接力、按反馈验证的做法，也适用于其他需要反复打磨的工作。产物和检查项按任务选用。

## 在 Codex 使用

下载或克隆本仓库，把其中的 `xcoze-paircraft/` 文件夹完整复制到个人 Skill 目录 `~/.agents/skills/`。确认入口路径为 `~/.agents/skills/xcoze-paircraft/SKILL.md`，然后在任务里调用 `$xcoze-paircraft`。如果列表里没出现，重启 Codex。团队可以把同一个 Skill 文件夹放进项目的 `.agents/skills/` 目录。

```text
使用 $xcoze-paircraft。我想做一个给小团队用的活动报名工具。
先一起梳理用户、核心流程和首版边界，这轮只讨论。
```

```text
使用 $xcoze-paircraft。根据已确认的流程做一个客户评审原型。
只做「填写报名 → 确认结果」这条路径，告诉我后续怎么修改表单文案。
```

```text
使用 $xcoze-paircraft。把报名确认页的主按钮改成「查看我的报名」，
点击进入报名详情。保留现有表单字段和提交规则，检查返回路径。
```

仓库包含 [Skill 入口](xcoze-paircraft/SKILL.md)、[协作模板](xcoze-paircraft/references/artifact-templates.md)、[完整示例](xcoze-paircraft/references/worked-example.md) 和 [安装说明](xcoze-paircraft/INSTALL.zh-CN.md)。Skill 本体由 Markdown 指令和可选的 Codex 界面元数据组成。

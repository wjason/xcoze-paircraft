# 示例：活动报名工具

这是一个虚构示例，展示如何把同一个产品从讨论推进到评审和改版。

## 1. 从一句想法开始

产品经理说：「想做个活动报名工具，先讨论下。」AI 先梳理组织者和参与者的任务，建议首版只验证「填表 → 提交 → 查看结果」。产品经理确认无需登录，名额限制留到后续讨论。这一轮交接一段简报和流程，待决定的问题单独保留。

## 2. 选择可评审的成果

下一轮要判断参与者能否看懂报名结果。团队选择一条可点击的报名路径，内容和演示数据集中维护，分享一个可以直接打开的版本。评审任务是「报名后找到自己的报名详情」。如果只需要决定流程顺序，一张带标注的线框就够。

## 3. 把反馈落到具体对象

反馈是「成功后这里不明显」。先定位到报名确认页的主按钮，和产品经理确认要解决的问题是找不到报名详情。把改动写清楚：

- 目标位置：报名确认页主按钮。
- 目标表现：按钮文案改为「查看我的报名」，点击进入详情。
- 保留项：原来的表单字段和提交规则。
- 检查：提交后看到新按钮，能进入详情并正常返回，重复提交规则保持原样。

AI 修改维护源并更新评审成品。产品经理以后可以用同一个页面名、选中图层或文案配置提出下一次修改。
